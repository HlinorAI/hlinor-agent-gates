# Spec: observability and lifecycle (v0.6)

Status: APPROVED by Owner 2026-10-13 (rev 2, all 5 decisions as recommended). Covers issues #8 and #9. Rev 2 answers 7 review points (enforced CLI, audit format, audit failure, notification secrets, locks, read-only semantics, lifecycle states) and adds phases.

## Goal

After v0.6, the Owner can answer in one command — and get told without asking:

> What is waiting for me, what is about to expire, what happened and who did it, and is the record of it intact?

And can remove agents and clean up gate leftovers without hand-editing worktrees, users or receipts. Nothing in v0.6 weakens an existing gate. Every command works in cooperative and enforced mode; enforced forms take `<project>` as first argument.

## 1. Commands and who may run them

| Command | Cooperative | Enforced | Changes state? |
|---|---|---|---|
| `status --all [--json] [--notify]` | anyone | agents via sudo; `--notify` root only | audit line only with `--notify` |
| `history [--since 7d] [--branch B] [--json]` | anyone | agents via sudo | no |
| `check-merge <acceptance-id>` | anyone | agents via sudo | audit line only |
| `list-agents [--json]` | anyone | agents via sudo | no |
| `audit verify [--expect-head H \| --expect-seq N]` | anyone | root | no |
| `audit reseal --reason TEXT` | Owner | root | audit only |
| `export-audit <file.tar.gz>` | Owner | root | no |
| `remove-agent <name> [--yes]` | Owner | root (`enforce remove-agent`) | worktree / user |
| `cleanup [--dry-run]` | Owner | root | gate temp files only |
| `enforce upgrade <project>` | — | root | code, sudoers |

Enforced sudoers (complete, replaces v0.4 block, installed by `enforce upgrade` after `visudo -c`):

```
Defaults:%agents env_reset, !setenv
%agents     ALL=(agent-gates) NOPASSWD: /opt/agent-gates/bin/agent-gates verify *, /opt/agent-gates/bin/agent-gates merge *, /opt/agent-gates/bin/agent-gates status *, /opt/agent-gates/bin/agent-gates history *, /opt/agent-gates/bin/agent-gates check-merge *, /opt/agent-gates/bin/agent-gates list-agents *, /opt/agent-gates/bin/gate-receive-pack *

agent-gates ALL=(ag-notify)   NOPASSWD: /opt/agent-gates/bin/ag-notify
```

`status --notify` is rejected when invoked through sudo by an agent (`DENY ROOT_REQUIRED`). `enforce upgrade` is the only way to move a v0.4/v0.5 install to v0.6; `enforce init` keeps refusing a differing sudoers file.

## 2. Audit log

### Format

`<receipts dir>/audit.jsonl`, one canonical JSON object per line (sorted keys, no spaces, UTF-8, `\n`):

```json
{"seq":42,"at":"…","event":"merge","actor":"agent-codex","project":"p","branch":"agent/codex","receipt":"<id>","result":"OK","prev":"<hash of seq 41>","hash":"<…>"}
```

- `hash` = sha256 hex of the canonical object **without** the `hash` key. `prev` = `hash` of the previous line; for `seq` 1, `prev` = 64 × `0`. `seq` increases by exactly 1.
- Every receipt written in v0.6 records `audit_seq` and `audit_prev` = the chain head **before** its own event.
- Owner clarification: `audit_seq` = N (own event), `audit_prev` = hash(N−1); recovery writes `recovered` at exactly N with that predecessor, otherwise `DENY AUDIT_BROKEN`; receipt-less events require an external head/sequence anchor.
- Owner compatibility clarification: legacy fixtures reserve a consistent audit slot to retain the original DENY checks; recovery tests trigger `verify`, not read-only `status`, and keep the unchanged-main assertion.
- Owner reseal clarification: `reseal` lists `invalidated_receipts` IDs from the discarded tail; those files remain evidence, are never recovered, and accept/merge deny `RECEIPT_INVALIDATED`; status shows `INVALIDATED`. Membership is determined by IDs in reseal, never by sequence numbers, and new events continue after reseal.

Owner phase B clarification: `publish attest --audit-export` validates an export manifest and signs `audit_head={seq,hash}` plus the full audit chain; Action validates hashes, receipt seq/prev anchors and ordering. A same-checkout publication can use its local audit.

### Events and order

Events: `verify`, `accept`, `merge`, `check_merge`, `deny`, `notify_failed`, `notified`, `remove_agent`, `cleanup`, `recovered`, `reseal`.

All appends happen under the project gate lock. For a state-changing command the order is fixed: **write and fsync the receipt → append and fsync the audit line → report success**. `merge` keeps its v0.4 pending journal; the audit line is appended after the ref update.

DENY events are logged only when the project is resolved and the gate lock is held. Earlier refusals (unknown project, usage errors, lock or log unavailable) go to stderr only — there is nowhere trustworthy to write them.

### Failure rules (fail-closed)

1. Audit file missing on first use → created with `seq` 1. Present but not verifiable (`audit verify` fails) → `verify`, `accept`, `merge` refuse with `DENY AUDIT_BROKEN`. Read-only commands still work and print the break.
2. Append fails (disk, permission) before success is reported → command reports `DENY AUDIT_UNAVAILABLE`. A receipt already written stays; it is not valid for the next step until recovered.
3. Recovery runs at the start of every state-changing command under the lock: any receipt or merge journal with no matching audit line gets a `recovered` line (`receipt`, original `created_at`). Recovery never invents results; it copies them from the signed receipt.
4. `audit reseal --reason` (Owner/root only) appends a `reseal` line whose `prev` is the hash of the last valid line and records the reason and the hash of the discarded tail. This is the only way past `AUDIT_BROKEN`, and it is visible forever.

### What it can and cannot detect

- Edit, reorder or delete of an inner line: always detected (`audit verify` names the first broken `seq`).
- Truncation of the tail: detected only against an external head — `--expect-head` / `--expect-seq`, the highest `audit_seq` referenced by a receipt, the publish attestation (`audit_head`, added when the range contains gate merges), or an export manifest. Written into `THREAT_MODEL.md`.
- Cooperative mode: tamper-evident given an external head. Enforced mode: agents cannot write the log at all.

## 3. Notifications

```
NOTIFY_CMD="…"                       # main's .agent-gates/config — policy file, change needs Owner override
NOTIFY_EVENTS="verify,merge,deny,expiring"
```

- After the audit line for a listed event is written, the gate runs the notifier with one JSON object on stdin (the audit line + a one-line `text`). Timeout 10 s, process group killed after. Result recorded as `notified` or `notify_failed`; neither of those events is ever notified (no loops). The gate result never changes.
- `expiring`: `status --all --notify` (root/Owner, scheduled by the Owner — cron/systemd example in README) emits one `expiring` per acceptance with < 2 h left, **once**: it skips an acceptance that already has a `notified` line for `expiring`.
- **Enforced mode: dedicated OS user `ag-notify`**, created by `enforce upgrade`, no login, not in `agents`, separate from `ag-runner`. Reason: `ag-runner` executes untrusted test code, so any secret it can read, tests can read. Secrets live in `/etc/agent-gates/notify.env` (root:ag-notify 0640). `ag-notify` cannot read receipts, keys or agent homes; it has its own lock and is fully killed (`pkill -u ag-notify`) after each run.
- Cooperative mode: the notifier runs as the calling user; README states that any agent can read its secrets in this mode.
- The kit ships examples only: `examples/notify/telegram.sh`, `examples/notify/slack.sh`. No network code in the gate, no secrets in the repo.

## 4. Status semantics

Per branch, one value each, first match wins:

- verification: `MERGED` (receipt used by a merge) → `STALE: BRANCH_MOVED` → `STALE: MAIN_MOVED` → `ACCEPT` / `REJECT` → `NONE`.
- acceptance: `USED` → `EXPIRED` → `EXPIRING (<2h)` → `VALID (expires in …)` → `NONE`.
- next step: derived from the two (e.g. `STALE` → `re-verify`; `ACCEPT` + `NONE` → `accept`; `VALID` → `merge`).

## 5. Read-only commands

- `check-merge` runs every `merge` check and stops. Guarantee: `main`, branches and receipts unchanged; it appends one `check_merge` audit line (with DENY code or `OK`).
- `export-audit` takes the gate lock, copies receipts, logs and `audit.jsonl` as one snapshot, writes `MANIFEST.json` (sha256 of every exported file except the manifest itself, chain `seq` and `head`, tool version), then releases the lock. The tarball is written outside the receipts directory.
- `history`, `list-agents`, `status` (without `--notify`), `audit verify` write nothing.

## 6. Lifecycle

`remove-agent <name>`:

| State | Result |
|---|---|
| worktree has uncommitted changes | `DENY DIRTY_WORKTREE` — always, no override; the Owner commits or discards by hand |
| verify running for this branch | waits on the gate lock, then re-checks |
| branch has commits not in `main` | allowed; prints them and keeps the branch (`--yes` skips the confirmation prompt only) |
| already removed | `ALREADY REMOVED`, exit 0 |
| enforced: archive target exists | new archive name with timestamp; never overwrites |

Removes the worktree only. Branch, receipts and audit are kept. Enforced (`enforce remove-agent`, root): locks the OS user, moves its home to `/var/lib/agent-gates/archive/<name>-<UTC timestamp>/`, removes it from `agents` and from the project registration; deletes nothing.

`cleanup` (under the gate lock): removes only gate-created temporary resources registered under `<common-dir>/agent-gates/tmp/` (cooperative) or `/var/lib/agent-gates/projects/<p>/tmp/` (enforced) that no running command holds. **Never** deletes lock files, receipts, logs, branches, agent worktrees or install-pending markers. `--dry-run` lists first.

## 7. Fix #9: crontab path on RHEL/Fedora

`enforce init`, `enforce upgrade` and `doctor` check both `/var/spool/cron/crontabs/ag-runner` and `/var/spool/cron/ag-runner` (and the same for `ag-notify`). Tested only in containers, including one RHEL-family image.

## Owner decisions (2026-10-13, all approved)

1. **Notifications through one `NOTIFY_CMD` hook plus example scripts**, no built-in integrations or secrets in the kit. Approved.
2. **Enforced mode: notifier runs as a separate `ag-notify` user** (not `ag-runner`, which runs untrusted tests; not `agent-gates`). Secrets in a root-owned file readable only by `ag-notify`. Approved.
3. **Audit log fail-closed**: a broken or unwritable log blocks verify/accept/merge; only the Owner's visible `audit reseal` unblocks. Approved.
4. **No command ever deletes receipts, logs, branches or locks**; `remove-agent` refuses dirty worktrees with no override. Approved.
5. **MCP server deferred to v0.7**; `check-merge` is the orchestrator hook in v0.6. Approved.
