# Spec: enforced local mode (v0.4)

Status: APPROVED by Owner 2026-10-09 (all 5 decisions as recommended). Covers issues #2–#6.

## Goal

After v0.4, on a Linux machine set up in enforced mode:

> An agent cannot move `main`, forge a receipt, edit the gate or its policy, or claim another agent's identity, **by any path the OS allows it** — not only by the commands we tell it to use.

v0.3 gates are cooperative: every agent runs as the same OS user, so the gate holds only while agents follow the rules. v0.4 turns the rules into file permissions and process boundaries. Cooperative mode stays the default; enforced mode is opt-in per project.

## Threat model in one paragraph

Agents are untrusted code with a shell. They may read anything their OS user can read, write anything it can write, run any binary, and leave background processes. They are **not** root and have no sudo rights except the gate rules below. The Owner is root (or a separate admin user). If an agent runs as root, nothing in this spec holds; `doctor` reports that as `NOT ENFORCED`.

## Architecture

```
agent-codex ─┐                      ┌─ /srv/agent-gates/<project>.git   (bare, owned by agent-gates)
agent-claude ├─ sudo (one command) ─┤  /var/lib/agent-gates/            (receipts, gate key, locks)
agent-zcode ─┘                      └─ sudo -u ag-runner → tests in a throwaway export
Owner (root) ── accept (signs with Owner key in /root) ── merge is done by the gate, never by git push
```

| OS user | Owns / can do | Cannot |
|---|---|---|
| `agent-<name>` (one per agent) | its own clone in `/home/agent-<name>/work/<project>`; read the bare repo; run the gate via sudo | write the bare repo, receipts, gate code, policy, keys |
| `agent-gates` (system, no login) | bare repos, receipts, gate signing key, locks | run tests itself; read the Owner key |
| `ag-runner` (system, no login) | a temp dir per test run | read gate state or any agent home; sudo |
| root (Owner) | Owner signing key; setup; `accept` | — |

Group `agents` contains every `agent-<name>` user and nothing else.

### Identity comes from the OS, not from flags

Every gate command an agent runs goes through `sudo -u agent-gates /opt/agent-gates/bin/agent-gates <cmd>`. sudo sets `SUDO_USER`, which the caller cannot override (env is reset, no `SETENV`). The gate maps `agent-<name>` → `<name>`. `--as` is removed in enforced mode:

- `verify` records `verifier = SUDO_USER`. Author = the branch's agent. Same → `SELF_VERIFICATION`.
- `merge` records `merged_by = SUDO_USER`.
- Pushes record `pusher = SUDO_USER` and may update only `refs/heads/agent/<pusher>`.

### Receipts are signed by the gate

The gate key (`/var/lib/agent-gates/gate_ed25519`, mode 600, owner `agent-gates`) signs every verification and merge receipt (`ssh-keygen -Y sign`, namespace `agent-gates-receipt`). The signed statement is "OS user X ran this command, and these were the results". Acceptance is signed by the Owner key (`/root/.ssh/agent-gates-owner`). Owner signature is **mandatory** in enforced mode; an unsigned acceptance is `BAD_SIGNATURE`.

This replaces the per-agent signing keys from ROADMAP v0.4 item 4 (see Decision 1).

## Commands (enforced mode)

| Who | Command | Effect |
|---|---|---|
| root | `agent-gates enforce init <repo> --agents codex,claude,zcode` | creates users, group, bare repo from current `main`, sudoers file, agent clones, gate key; idempotent |
| agent | `git push gate agent/<me>` | via restricted receive-pack, only own branch |
| agent | `sudo -u agent-gates agent-gates verify <project> agent/<author>` | tests the merge result as `ag-runner`, writes signed receipt |
| root | `agent-gates accept <id>` | shows diff and risks, Owner-signed acceptance |
| agent | `sudo -u agent-gates agent-gates merge <project> <acceptance-id>` | all v0.2 checks + signatures, then moves `main` inside the bare repo |
| any | `agent-gates doctor [<project>]` | reports every check below; exit 1 on any failure |

### Push path

Agents read the bare repo through group `agents` (mode 750 dirs, 640 files); `enforce init` adds `safe.directory=/srv/agent-gates/*` to each agent user's git config, since the repo is owned by another user. Agent clones have `remote.gate.url = /srv/agent-gates/<project>.git` and `remote.gate.receivepack = sudo -u agent-gates /opt/agent-gates/bin/gate-receive-pack`. The wrapper accepts only a path under `/srv/agent-gates/`, sets `AG_PUSHER` from `SUDO_USER`, and execs `git-receive-pack`. The bare repo's `pre-receive` hook:

- allows create/update/delete of `refs/heads/agent/<pusher>` only;
- rejects any update to `main`, tags, or another agent's branch — `main` is never pushed by anyone.

### Merge without a working tree

`merge` runs inside the bare repo as `agent-gates`: `git commit-tree <merge_tree> -p <base> -p <head>` with the receipt ids in the message, then `git update-ref refs/heads/main <new> <base>` (compare-and-swap, so a moved main fails atomically → `MAIN_MOVED`). The check that the merge commit's tree equals `merge_tree` is now true by construction.

### Test runs

1. `agent-gates` exports the merge commit with `git archive` into a fresh dir owned by `ag-runner` (no `.git`, so tests cannot reach the gate repo).
2. Runs `TEST_CMD` from **main's** policy as `ag-runner` (`sudo -u ag-runner`, sudoers grants only this to `agent-gates`), with the v0.3.1 timeout.
3. After the run, kills every process of `ag-runner` (`pkill -KILL -u ag-runner`) and deletes the dir. Background children cannot survive or write gate state.
4. Runner use is serialized machine-wide by a lock (one test run at a time). Baseline runs the same way.

### Receipts bind policy and test command (issue #6)

Verification receipt adds `policy_sha` (tree hash of `.agent-gates/` at `base_sha`) and `test_cmd_sha256`. `merge` recomputes both from current main; any difference → `POLICY_CHANGED_SINCE_VERIFY`.

## sudoers (complete file, installed by `enforce init`, checked with `visudo -c`)

```
Defaults:%agents env_reset, !setenv
%agents     ALL=(agent-gates) NOPASSWD: /opt/agent-gates/bin/agent-gates verify *, /opt/agent-gates/bin/agent-gates merge *, /opt/agent-gates/bin/agent-gates status *, /opt/agent-gates/bin/gate-receive-pack *
agent-gates ALL=(ag-runner)   NOPASSWD: /opt/agent-gates/bin/ag-run *
```

`/opt/agent-gates/` is owned by root, mode 755, files 755. The CLI validates every argument itself; sudoers only limits which binary runs.

## Done when — effect reachability (issue #2 acceptance)

Each test runs as a real `agent-codex` user on a CI Linux runner and asserts the **effect** (`main` unchanged, file unchanged), not the error text.

| # | Attack as `agent-codex` | Expected effect |
|---|---|---|
| 1 | `git push gate HEAD:main` | main unchanged |
| 2 | `git push gate HEAD:agent/claude` | other branch unchanged |
| 3 | write to `refs/`, `packed-refs`, `objects/`, `config`, `hooks/` of the bare repo | EACCES, repo unchanged |
| 4 | edit `/opt/agent-gates/*` or main's `.agent-gates/` through the filesystem | EACCES |
| 5 | write, edit or delete a receipt in `/var/lib/agent-gates` | EACCES |
| 6 | read the gate key or the Owner key | EACCES |
| 7 | `sudo -u agent-gates bash`, `sudo -u agent-gates git …`, `sudo -u ag-runner …` | denied by sudo |
| 8 | `sudo VAR=x -u agent-gates agent-gates …` (env injection) | denied by sudo |
| 9 | verify own branch (author = caller) | `SELF_VERIFICATION`, no receipt |
| 10 | branch test code writes into gate state, the agent homes, or leaves a background process | writes fail; no `ag-runner` process after verify |
| 11 | merge with an acceptance not signed by the Owner key | `BAD_SIGNATURE`, main unchanged |
| 12 | `git worktree add` / `git --git-dir` pointing at the bare repo | cannot write, main unchanged |
| 13 | push an `agent/codex` branch that edits `.agent-gates/` or `pre-receive` | lands on the branch only; policy deny at accept (v0.3.1) |
| 14 | agent process running as root | `doctor` → `NOT ENFORCED`, exit 1 |

Plus the existing v0.2/v0.3 suites, re-run in enforced mode.

## `doctor` checks (issue #6)

git ≥ 2.38; users and group exist; no agent user in `sudo`/`wheel`/`root` groups; sudoers file matches the expected hash; ownership and modes of `/opt/agent-gates`, `/srv/agent-gates`, `/var/lib/agent-gates`; gate key and Owner allowed_signers present; `pre-receive` hook matches the expected hash; no process of an agent CLI (`codex`, `claude`, …) running as root; no `ag-runner` process idle; stale locks; acceptances expiring within 2 h.

## Out of scope for v0.4

- macOS enforced mode (users/sudoers differ; Linux first, see Decision 2).
- Containers per agent (optional later).
- Network isolation of test runs.
- GitHub-side enforcement (v0.5, issue #7).
- Migrating Hlinor's own agents to agent users — separate operational task after the kit ships.

## Owner decisions (2026-10-09, all approved)

1. **Identity via OS users + sudo, receipts signed by one gate key — instead of per-agent keys.** Per-agent keys would sit in each agent's home; the OS already proves who called. Approved.
2. **Enforced mode is Linux-only in v0.4.** macOS stays cooperative. Approved.
3. **One shared test-runner user, one test run at a time.** Simple and safe; parallel runners later. Approved.
4. **`main` moves only inside the gatekeeper; nobody pushes `main`, including the Owner.** The Owner publishes to GitHub from `/srv/agent-gates/<project>.git` (publish script path changes). Approved.
5. **Gate CLI installed to `/opt/agent-gates` as root, not run from the repo.** A branch can never change the code that judges it. Approved.
