# Spec: verify / accept / merge (v0.2)

Status: APPROVED by Owner 2026-10-08. Open questions resolved as recommended: strict `MAIN_MOVED`, baseline on by default, signing off by default (mandatory in enforcement mode), TTL 24h.

## Goal

Turn the Coder → Verifier → Owner → Git Agent policy into commands that **refuse** when a step is missing. After v0.2:

> A merge into main happens through `agent-gates merge` only if an independent Verifier tested **exactly the code that will land**, and the Owner accepted **that** verification. Any new commit, any change to main, or an expired acceptance invalidates it.

Scope note: in v0.2 the commands are the gate, but a same-user agent can still call `git merge` directly. Making the commands the *only* path is the enforcement mode (separate clones and OS users), specified separately. This spec designs receipts so that enforcement mode can reuse them unchanged.

## Commands

```
agent-gates verify <branch> --as <verifier>    # run tests on the merge result, write a verification receipt
agent-gates accept <verification-id>           # Owner accepts, writes an acceptance receipt
agent-gates merge  <acceptance-id>             # re-check everything, merge, write a merge receipt
agent-gates status [<branch>]                  # show receipts and whether they are still valid
```

All commands: run from anywhere, operate on the main repo found via `.agent-gates/config`. Exit 0 = success, 1 = refused (gate), 2 = usage or environment error. Every refusal prints one line `DENY <REASON_CODE>: <human text>`.

## 1. `verify`

1. Preconditions, else DENY:
   - `<branch>` matches `agent/<name>`; `<name>` is the **author**. `--as <verifier>` must differ from `<name>` → `SELF_VERIFICATION`.
   - Main repo working tree is clean → `MAIN_DIRTY`.
2. Record `base_sha` = current main HEAD, `head_sha` = branch head.
3. Compute the merge result without touching any checkout: `git merge-tree --write-tree base_sha head_sha` → `merge_tree` (tree OID). Conflicts → `MERGE_CONFLICT`.
4. Create a throwaway worktree at a detached commit of `merge_tree` (parents `base_sha`, `head_sha`). Run the configured `TEST_CMD` there. Capture exit code, last non-empty output line (`summary`), sha256 of full output (`output_sha256`), duration. Remove the worktree.
5. Baseline: run `TEST_CMD` on `base_sha` the same way (skippable with `--no-baseline`, recorded as skipped).
6. Verdict: `ACCEPT` if the merge-result tests exit 0, else `REJECT`. A REJECT receipt is still written. It is evidence too.
7. Write the receipt, print its id.

Tests run on the **merge result**, not on the branch alone. That is what lands in main, and it catches "branch passes, main passes, the combination breaks".

## 2. `accept`

1. Load the verification receipt. DENY if `verdict != ACCEPT` → `NOT_ACCEPTED_BY_VERIFIER`.
2. Re-check freshness: current main HEAD == `base_sha` → else `MAIN_MOVED`; branch head == `head_sha` → else `BRANCH_MOVED`.
3. Re-check verification `test_cmd` against `TEST_CMD` from main config; mismatch → `TEST_CMD_MISMATCH`. Show the Owner: author, verifier, commits in `base..head`, diffstat, test command, test summary, baseline summary. Ask for typed confirmation (`yes`). `--yes` skips the prompt for scripted use.
4. Sign (see Signing) and write the acceptance receipt with `expires_at` = now + `ACCEPT_TTL` (default 24h).

## 3. `merge`

Re-checks everything at the moment of merging. Any failure is a DENY:

| Check | Reason code |
|---|---|
| acceptance receipt exists, hash matches content | `RECEIPT_TAMPERED` |
| acceptance signature valid (when signing enabled) | `BAD_SIGNATURE` |
| not expired | `ACCEPTANCE_EXPIRED` |
| verification receipt it points to exists and its hash matches | `RECEIPT_TAMPERED` |
| verdict ACCEPT, verifier ≠ author | `NOT_ACCEPTED_BY_VERIFIER` / `SELF_VERIFICATION` |
| verification `test_cmd` == `TEST_CMD` from main config | `TEST_CMD_MISMATCH` |
| main HEAD == `base_sha` | `MAIN_MOVED` |
| branch head == `head_sha` | `BRANCH_MOVED` |
| main working tree clean | `MAIN_DIRTY` |
| `git merge-tree --write-tree base head` == recorded `merge_tree` | `MERGE_RESULT_CHANGED` |
| receipt not already used by an earlier merge | `RECEIPT_REUSED` |

Then `git merge --no-ff head_sha` with a message that includes the verification and acceptance ids, assert the new commit's tree == `merge_tree` (`MERGE_RESULT_CHANGED`, merge aborted), and write a merge receipt.

`MAIN_MOVED` is deliberate: if anything else landed on main since verification, the combination was never tested, so re-run `verify`.

## Receipts

Location: `<git-common-dir>/agent-gates/receipts/`. That is inside `.git`, so it is not tracked and is shared by all worktrees. One JSON file per receipt. Name: `<kind>-<id>.json`, where `id` = first 12 hex chars of `sha256` of the canonical JSON content (sorted keys, no whitespace, `id` field excluded).

```json
{
  "kind": "verification",
  "schema": 1,
  "id": "a1b2c3d4e5f6",
  "repo": "<absolute main repo path>",
  "branch": "agent/codex",
  "author": "codex",
  "verifier": "claude",
  "base_sha": "<40 hex>",
  "head_sha": "<40 hex>",
  "merge_tree": "<40 hex>",
  "test_cmd": "python3 -m pytest tests -q",
  "result":   {"exit": 0, "summary": "102 passed in 0.99s", "output_sha256": "<64 hex>", "seconds": 3.1},
  "baseline": {"exit": 0, "summary": "87 passed in 0.85s", "output_sha256": "<64 hex>", "seconds": 2.8},
  "verdict": "ACCEPT",
  "created_at": "2026-10-09T10:00:00Z",
  "tool_version": "0.2.0"
}
```

```json
{
  "kind": "acceptance",
  "schema": 1,
  "id": "…",
  "verification_id": "a1b2c3d4e5f6",
  "verification_sha256": "<64 hex of the verification file content>",
  "owner": "andrei",
  "created_at": "…",
  "expires_at": "…",
  "signature": "<ssh signature armor, or null when signing is off>"
}
```

```json
{
  "kind": "merge",
  "schema": 1,
  "id": "…",
  "acceptance_id": "…",
  "merge_commit": "<40 hex>",
  "merged_by": "codex",
  "created_at": "…"
}
```

Full test output is kept next to the receipt as `<id>.log`. Its hash is in the receipt.

## Signing (acceptance only)

- Uses `ssh-keygen -Y sign` / `-Y verify` with namespace `agent-gates`. No new dependencies, same mechanism git uses for SSH-signed commits.
- Config: `OWNER_SIGNING_KEY` (private key path, used by `accept`) and `.agent-gates/allowed_signers` (tracked, public key of the Owner, used by `merge`).
- If `OWNER_SIGNING_KEY` is unset, acceptance is unsigned and `status` shows `UNSIGNED`. In enforcement mode signing will be mandatory.
- What it buys even in v0.2: an agent that forges an acceptance file can't produce a valid signature without the Owner's private key. Keep that key out of agents' reach (it lives on the Owner's machine or in the Owner's ssh-agent, not in the repo).

## Config additions (`.agent-gates/config`)

```
TEST_CMD="python3 -m pytest tests -q"
ACCEPT_TTL_HOURS=24
OWNER_NAME="owner"
OWNER_SIGNING_KEY=""          # empty = unsigned acceptances
```

`init.sh` writes these. All CLI copies read config only from the main checkout, never from an author worktree. `TEST_CMD` moves from the docs into config so `verify` and the docs can't disagree.

## Tests required before release (negative first)

Each one asserts the exact reason code and that **main did not change**:

1. verify with `--as` equal to the author → `SELF_VERIFICATION`
2. verify while main is dirty → `MAIN_DIRTY`
3. failing tests → receipt with `REJECT`; accept on it → `NOT_ACCEPTED_BY_VERIFIER`
4. new commit on branch after verify → accept and merge → `BRANCH_MOVED`
5. new commit on main after verify → `MAIN_MOVED`
6. edit any byte of the verification receipt → `RECEIPT_TAMPERED`
7. edit the acceptance (e.g. extend `expires_at`) with signing on → `BAD_SIGNATURE`
8. acceptance past TTL → `ACCEPTANCE_EXPIRED`
9. merge the same acceptance twice → second is `RECEIPT_REUSED`
10. conflicting branch → verify gives `MERGE_CONFLICT`
11. happy path: verify → accept → merge; merge commit tree == `merge_tree`; three receipts present

## Implementation constraints

- Bash for the CLI entry point, python3 (stdlib only) for JSON, hashing and checks. Same requirements as v0.1, plus git ≥ 2.38 for `merge-tree --write-tree` (checked at start, `DENY GIT_TOO_OLD`).
- No network, no new packages.
- Must run on Linux and macOS (CI matrix already exists).

## Out of scope for v0.2

- Separate clones / OS users (enforcement mode), separate spec.
- Comparing test counts between baseline and result automatically (runner-specific output parsing). The summary lines are recorded so a human can compare.
- GitHub branch protection or PR integration.
- Signing verification receipts by the Verifier.

## Decisions (Owner, 2026-10-08)

1. `MAIN_MOVED` is strict: any change to main invalidates a verification.
2. Baseline run is on by default (`--no-baseline` to skip, recorded in the receipt).
3. Acceptance signing is off by default in v0.2; `status` shows `UNSIGNED`. Mandatory in enforcement mode.
4. Acceptance TTL: 24 hours (`ACCEPT_TTL_HOURS`).
