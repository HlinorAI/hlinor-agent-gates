# Spec: automatic install on new projects (v0.3)

Status: APPROVED by Owner 2026-10-08 (including fail-closed default TEST_CMD).

## Goal

When a new project is started on a configured machine, **no matter which agent or human runs `git init`**, the project gets agent-gates on its first commit: policy files, per-agent worktrees, and instruction files that every common agent reads. An agent that is not in the default list creates its own worktree on first contact.

## Owner decisions (2026-10-08)

1. Default agents: `codex, claude, zcode`. Any other agent that opens the project creates its own worktree via `add_agent.sh <name>`.
2. Auto-install only under the Owner's project roots (configured list). Nothing happens anywhere else.
3. Cloned or existing repositories are never auto-installed: the Owner is asked (or notified once, when there is no terminal).

## Why git, not agent instructions

Each agent reads a different instruction file and may ignore it. Every agent uses git. So the trigger is a git hook installed through the global template directory, and agent instruction files are the second layer.

## 1. One-time machine setup: `setup-global.sh`

```
./setup-global.sh [--agents a,b,c] [--root DIR]... [--uninstall] [--dry-run]
```

Creates (idempotent, re-running changes nothing):

| Path | Content |
|---|---|
| `~/.agent-gates/kit/` | copy of this kit (stable path for hooks) |
| `~/.agent-gates/defaults` | `AGENTS="codex,claude,zcode"`, `OWNER_NAME`, `TEST_CMD` (see below) |
| `~/.agent-gates/roots` | one absolute, resolved path per line (paths may contain spaces) |
| `~/.agent-gates/git-template/hooks/post-commit` | the trigger |
| global git config | `init.templateDir = ~/.agent-gates/git-template` |
| agent global rules | a marked block in `~/.claude/CLAUDE.md`, `${CODEX_HOME:-~/.codex}/AGENTS.md`, `~/.gemini/GEMINI.md` (only for files whose parent dir exists) |

Rules:
- If `init.templateDir` is already set to something else → refuse, print what to do, change nothing.
- Marked blocks are delimited by `<!-- agent-gates:begin -->` / `<!-- agent-gates:end -->`. Re-run replaces the block, never duplicates it. Text outside the block is never touched.
- `--uninstall` removes the git config entry and the marked blocks; leaves `~/.agent-gates/` and installed projects alone.

## 2. The trigger: `post-commit` hook

Copied into every repository created by `git init` or `git clone` on this machine. Behavior, in order; the first matching rule wins. The hook never fails the commit and finishes in < 100 ms when it doesn't apply.

1. `AGENT_GATES_INSTALLING=1` in env, or `.agent-gates/` exists → exit (recursion guard / already installed).
2. Repo top-level (resolved) is not under any path in `~/.agent-gates/roots` → exit silently.
3. Current checkout is a linked worktree, not the primary → exit.
4. **Existing project** = HEAD has a parent, or any remote is configured.
   - Marker `.git/agent-gates-offered` exists → exit.
   - stdin is a TTY → ask `Install agent-gates in this repo? [y/N]`; `y` → install as in 5.
   - otherwise → print once `agent-gates: not installed here. To install: ~/.agent-gates/kit/init.sh <repo> --from-defaults`.
   - write the marker in both cases (asked once per clone).
5. **New project** (first commit, no remote) → run `AGENT_GATES_INSTALLING=1 ~/.agent-gates/kit/init.sh <repo> --from-defaults`.
   - init refuses a dirty tree (unchanged v0.1.1 rule) → print one line, **no marker**, so the next commit retries.
   - kit missing → print one line with the setup command.

## 3. `init.sh` additions

- `--from-defaults`: read agents, owner, test command from `~/.agent-gates/defaults`; explicit flags still override.
- **Test command fail-closed.** If none is configured, write `TEST_CMD="echo 'agent-gates: TEST_CMD not configured' >&2; exit 1"`. Every `verify` is then REJECT until the Owner sets a real command in main's `.agent-gates/config`. Never default to a command that passes.
- **Project instruction files.** Write a marked block into `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` at repo root: create the file if missing, append the block if the file exists, replace the block if already present. Block content:

```markdown
<!-- agent-gates:begin -->
## Multi-agent rules (agent-gates)

1. Read `GIT_POLICY.md` before any change.
2. Your name is your product name in lowercase (codex, claude, zcode, gemini, cursor, manus, kimi, ...).
3. If your working directory is `{{MAIN_REPO}}`: stop editing here.
   - If `{{WT_ROOT}}/<name>` does not exist, create it: `{{MAIN_REPO}}/.agent-gates/add_agent.sh <name>`
   - Work only in `{{WT_ROOT}}/<name>` on branch `agent/<name>`.
4. Never merge into `{{MAIN_BRANCH}}`, never push, never run the gate CLI from your own worktree copy.
<!-- agent-gates:end -->
```

- These three files are committed in the same install commit.

## 4. Global agent rule block (layer 3, backstop)

Installed by `setup-global.sh` into the global files listed above:

```markdown
<!-- agent-gates:begin -->
## agent-gates (machine-wide)
- In any git repo with `.agent-gates/`: follow the repo's AGENTS.md block and GIT_POLICY.md.
- In a repo under my project roots (`~/.agent-gates/roots`) without `.agent-gates/`:
  - if it has no remote and you are about to make or have just made its first commit → run `~/.agent-gates/kit/init.sh <repo> --from-defaults`, then move to your worktree.
  - otherwise → tell the Owner it is not installed; do not install yourself.
<!-- agent-gates:end -->
```

## 5. `add_agent.sh` (unchanged behavior, one addition)

Prints the path to switch to and the project rule to follow. Name validation stays `^[a-z0-9-]+$`.

## Tests required (each asserts the observable result and that nothing else changed)

1. New repo under a root: `git init` + first commit → `.agent-gates/` exists, 3 worktrees, `AGENTS.md`/`CLAUDE.md`/`GEMINI.md` contain the block, tree clean.
2. New repo outside all roots → no `.agent-gates/`, no worktrees, no output.
3. Root path with spaces works.
4. Cloned repo (has remote) without TTY → no install, notice printed exactly once across two commits.
5. Repo whose HEAD has a parent but no remote → treated as existing (same as 4).
6. Dirty tree after first commit → no install, no marker; after a clean commit → installed.
7. Recursion: the install commit does not re-trigger install (exactly one install commit).
8. Existing `AGENTS.md` with user text → user text intact, block appended once; re-run → still one block.
9. Unknown agent `manus`: `add_agent.sh manus` from the block's instruction → worktree `agent/manus`.
10. `setup-global.sh` twice → one block per global file, one `init.templateDir` entry.
11. Foreign `init.templateDir` already set → setup refuses, config unchanged.
12. `--uninstall` → git config entry and global blocks removed, other text intact.
13. No test command configured → `verify` gives REJECT; main unchanged.
14. Hook on a repo where the kit is missing → commit succeeds, one-line notice.

All tests run in temporary `HOME` and temporary git config (`GIT_CONFIG_GLOBAL`), never touching the real machine settings. Linux and macOS CI.

## Out of scope for v0.3

- Auto-detecting the test command from project files (pytest / npm / go). Possible v0.3.x, opt-in.
- Installing into existing repos in bulk.
- Making the hook impossible to skip (`--no-verify` does not skip post-commit, but deleting the hook or `init.templateDir` does; same-user limit, as in v0.2).
